Proposed Projects: WordPress + React/Gutenberg Blocks

Use these as portfolio projects, interview take-homes, or “talk tracks.” Each is scoped so you can ship a strong MVP, then iterate with performance, accessibility, testing, and editor UX.

← Questions Flashcards Code Challenges

1) Block Library: “Marketing Sections”

Gutenberg React Great for agencies
  • Create 6–10 reusable blocks: Hero, Features, Testimonials, FAQ, Pricing, CTA.
  • Design tokens via theme.json (colors/typography/spacing).
  • Block controls: alignments, presets, responsive toggles, “stack on mobile”.
  • Accessibility: keyboard-friendly controls + correct headings/landmarks.
  • Deliverables: npm build + WP plugin + demo site with patterns.

2) Dynamic Block: “Related Content” (Query + Caching)

Dynamic block PHP Performance
  • Block renders server-side (PHP) using render_callback.
  • Editor uses React to preview and configure (taxonomy, limit, sort).
  • Cache rendered output with transients; invalidate on post/tax changes.
  • Explain tradeoffs: transient keys, object cache support, TTL strategy.

3) Headless WP + React Frontend (Next.js or Vite)

WP REST React Architecture
  • WP exposes content via REST (or WPGraphQL if you prefer).
  • Frontend renders pages, handles routing, and caches responses.
  • Auth: preview drafts using application passwords or JWT.
  • Deploy: static ISR-like strategy or server render; document decisions.

4) “Form Builder” Block: Validations + Anti-Spam

Gutenberg Security Real-world
  • Build a block that outputs a form with configurable fields.
  • Server handler: nonce verification + sanitize/validate + rate limiting.
  • Add honeypot + time-based checks; optionally reCAPTCHA.
  • Store submissions as CPT; export CSV; basic admin UI.

5) Editorial Workflow: “Review & Publish” Tools

WP Admin UX Testing
  • Custom status flow or checklist: Draft → Review → Approved.
  • Block-level validation: prevent publish if required blocks missing.
  • Notifications: emails/Slack webhook when status changes.
  • Add automated checks: broken links, missing alt text, heading order.

6) “Media Optimizer” Plugin: Images + LCP

Performance Core Web Vitals Senior talking points
  • Detect oversized hero images and generate optimized sizes.
  • Improve LCP: preload critical images + font strategy.
  • Lazy-load non-critical images; ensure layout stability.
  • Measure: Lighthouse before/after + explain why changes help.

7) Block + Integration: “CRM Signup”

REST Integrations Agency work
  • Gutenberg block renders signup form with segment/tag controls.
  • Server proxy endpoint to CRM (HubSpot/Mailchimp/etc).
  • Secure secrets: keep tokens server-side; rotate; log failures safely.
  • Observability: structured logs + admin retry queue (optional).

8) Multisite “Tenant Theme” Starter

Multisite theme.json Scalability
  • Multisite with per-site branding tokens (colors/logo) stored as options.
  • Shared block patterns; per-tenant overrides via theme.json filters.
  • Hardening: disable risky file edits, restrict capabilities, audit plugin list.

9) “Docs Site” Theme: MD → WP Blocks

Content Parsing Editor UX
  • Import Markdown docs and convert into block markup.
  • Shortcodes to blocks migration helpers.
  • Syntax highlighting + copy buttons + anchor links.

10) Testing Pack: Blocks + PHP + E2E

Testing Playwright/Cypress Senior signal
  • Unit tests for PHP helpers; integration tests for REST endpoints.
  • E2E: create post, insert block, publish, validate frontend output.
  • Explain CI: run tests on PR, cache dependencies, artifacts for screenshots.
How to present these in interviews:
  • Show the repo structure: plugin folder, build tooling, and why you chose it.
  • Explain tradeoffs: dynamic vs static blocks, caching and invalidation, editor UX constraints.
  • Call out accessibility, performance metrics, and security controls (nonces, capability checks).
  • Have 2–3 “failure stories” ready: what broke and how you debugged it.
