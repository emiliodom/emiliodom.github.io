Rendering & Streaming

Interview Questions: Suspense, Streaming, and Partial Prerendering

Q1: What is Streaming in Next.js and how does it improve UX?

Concept: Streaming allows you to break down the page's HTML into smaller chunks and progressively send them from the server to the client.

Benefit: Instead of waiting for the entire page's data to be fetched before showing anything (blocking), the user sees the initial UI (layout, navbar) immediately. Slow data-fetching components show a loading state (Suspense fallback) and then "pop in" when ready.

Mechanism: It uses HTTP Transfer-Encoding: chunked.

Q3: What is Partial Prerendering (PPR)?

Concept: PPR is an experimental feature that combines static and dynamic rendering in the same route.

How it works: The shell of the application is prerendered at build time (static), leaving "holes" for dynamic content. When a request comes in, the static shell is sent immediately, and the dynamic parts are streamed in parallel.

Difference from standard Streaming: Standard streaming usually happens at request time for the whole page. PPR pre-computes the static parts during the build.
