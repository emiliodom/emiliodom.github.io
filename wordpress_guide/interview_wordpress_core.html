WordPress Core Architecture Interview Questions

Deep dive into Hooks, Database Schema, and the Request Lifecycle.

Understanding the core architecture is what separates a "site builder" from a WordPress Engineer. These questions cover the internal mechanisms of WordPress.

1. Explain the WordPress Request Lifecycle (Loading Sequence).

Answer: A high-level overview of what happens when a request hits WordPress:

  1. index.php: Entry point.
  2. wp-blog-header.php: Loads the environment.
  3. wp-load.php: Bootstraps WordPress (config, db).
  4. wp-settings.php: Loads core libraries, plugins, and the active theme's `functions.php`.
  5. init hook: Core is fully loaded.
  6. wp() (Main Query): Parses the URL and runs the main database query to determine what content to show.
  7. template_redirect: Decides which template file to load.
  8. template-loader.php: Loads the template (e.g., `single.php`).
  9. Shutdown: PHP execution ends.

2. What is the difference between `actions` and `filters`?

Answer: Both are "Hooks", but they serve different purposes:

  • Actions (`do_action` / `add_action`): Events where you can "do" something at a specific point (e.g., echo HTML, send an email, update DB). They do not return a value.
  • Filters (`apply_filters` / `add_filter`): Used to modify data. They take a variable, modify it, and must return it.
// Action: Do something
add_action('wp_footer', function() {
    echo '<!-- Analytics Code -->';
});

// Filter: Modify data
add_filter('the_title', function($title) {
    return 'Prefix: ' . $title;
});

3. Describe the WordPress Database Schema. What are the core tables?

Answer: WordPress uses a relational database (MySQL/MariaDB). Key tables include:

  • `wp_posts`: Stores posts, pages, attachments, nav menu items, and revisions.
  • `wp_postmeta`: Key-value storage for extra post data (custom fields).
  • `wp_users` & `wp_usermeta`: User data.
  • `wp_options`: Site configuration and settings.
  • `wp_terms`, `wp_term_taxonomy`, `wp_term_relationships`: Categories, tags, and custom taxonomies.

Follow-up: Why is `wp_postmeta` often a performance bottleneck? (Answer: It's an EAV - Entity Attribute Value - table, making complex filtering slow and inefficient).

4. What is the Template Hierarchy?

Answer: The logic WordPress uses to decide which theme file to render for a given request. It searches from specific to generic.

Example for a Single Post:

  1. `single-{post_type}-{slug}.php`
  2. `single-{post_type}.php`
  3. `single.php`
  4. `singular.php`
  5. `index.php` (Fallback)

5. How does the Rewrite API work?

Answer: The Rewrite API maps incoming URLs (Permalinks) to database queries.

  • WordPress uses regex to match the URL structure.
  • It converts the match into "Query Variables" (e.g., `index.php?p=123`).
  • These variables are passed to `WP_Query` to fetch content.

Important: You must flush rewrite rules (`flush_rewrite_rules()`) after adding new custom post types or rewrite rules, but never on every page load (only on plugin activation).
